## Browser coverage

The added regression verifies sending, editing and deletion synchronize without any account bootstrap request. Two actual accounts exchange messages; editing, pins, replies and attachments survive database refresh and page reload. Community creation generates a durable expiring invitation. Mission objectives persist and reward claims update server state. Appearance settings persist; devices list actual sessions. Disabled provider state and authorized global search work. Registration creates a real identity, runs interest onboarding and retains it after reload.

Two browser contexts exchange camera video in both directions and microphone audio through actual WebRTC connections to LiveKit. Screen capture reaches the remote participant; stopping share removes that state. Leaving closes the call and updates the remote participant list. A separate run joins 13 real browser participants to one room, checks the SFU participant count, confirms one active WebRTC peer connection per browser and exercises the 12-person page boundary. Capture uses Chromium synthetic devices, not mocked application media. Temporary initial transport failures receive bounded retry without retrying authorization failures.

Axe checks Home, Missions, Account, Administration and Voice for serious/critical WCAG A/AA violations. Mobile checks exercise Home, Missions, Account and Voice at 390×844 without horizontal overflow. This is automated evidence, not accessibility certification. Earlier iterations uncovered composer timing, transceiver negotiation, a contrast issue and stale test selectors; these were corrected before the successful complete run.

## Artifacts and limits

Screenshots are under screenshots/live-*.png, including cinematic sign-in, Home, community chat, missions, leaderboard, integrations, devices, administration, voice, mobile and actual synthetic screen sharing. scripts/live-inspect.mjs refreshes desktop captures; scripts/smoke-container.mjs exercises the production image and removes its temporary container/environment file.

The runtime container test used local HTTP and the development database TLS exception against the isolated database. It does not prove public DNS/HTTPS issuance or production database certificates. Production configuration requires those controls; a public environment was not deployed.

External OAuth consent/token refresh and public WebRTC connectivity across separate restrictive networks were not tested without provider/deployment credentials. Local HTTP/WebSocket regression load, SFU media regression and two-process replica checks passed; see PERFORMANCE.md for the exact fixture and results. No production-scale soak, independent penetration test, production backup restoration drill or cross-browser Safari/Firefox certification was performed. Sensitive request logging remains disabled.

Real YouTube, Spotify and SoundCloud links were resolved through each provider's public official metadata endpoint and accepted as embedded playback tracks. The browser regression verifies trusted player creation, shared state rendering and stop cleanup with a deterministic SDK substitute; it does not assert audible DRM media in headless Chromium. The provider controls autoplay, account eligibility, geography and whether Spotify supplies a full track or preview. Direct native audio remains disabled until an operator adds controlled HTTPS origins to `MUSIC_AUDIO_HOSTS`; URL validation and the FFmpeg-to-LiveKit publication path are covered independently.
